## §2 Binding conventions (duplicated from MASTER_SPEC on purpose)

1. Security posture is monotonic — never weaken validation, caps, `O_NOFOLLOW`, sanitizers, fail-closed branches.
2. Counts are generated, never hand-typed.
3. No mocks in tests. Real temp dirs, real subprocesses.
4. `make check` green before "done"; counts gate never waived.
5. Tool-count changes are atomic (registry + contract + counts + docs in one commit).
6. Ruff config stays `select = ["E","F","W"]`, line-length 120 — do not expand lint scope ad hoc.
7. Python ≥ 3.10 compatibility (CI runs 3.12; do not use 3.12-only syntax).
8. Commit style `M<n>.<i>: imperative summary`.

## §3 Non-goals (binding)

- No Windows support (platform_check stays POSIX-only).
- No new storage backend (gzipped JSON + content dir stays; no SQLite migration). [DECISION] The format is battle-tested with atomic-write and bomb-cap hardening; a storage rewrite risks the security core for zero user-visible gain at this corpus size.
- No web UI, no HTTP transport. stdio MCP only.
- No LSP integration in this spec's scope (revisit after Stage 3; see SPEC_5 §3 [DECISION] D12).
- No new runtime dependencies without a spec amendment, except those named in SPEC parts (fastembed extra, pip-audit dev-side, openai optional extra in SPEC_6 §3).

## §5 Makefile (create at repo root in M0 — exact content)

[DECISION] D2: Introduce a Makefile as the single "done" gate; `make check` = lint + typecheck + counts + full tests. Rationale: the skill's enforcement model needs one never-waive command, and today's `ci-local.sh` misses mypy and the counts gate (which is exactly how drift reached `main`).

```make
.PHONY: check lint typecheck counts test test-fast stamp contract

check: lint typecheck counts test

lint:
	uv run --with ruff ruff check .

typecheck:
	uv run --group typecheck mypy

counts:
	uv run python scripts/check_counts.py

test:
	uv run pytest --tb=short -q

test-fast:
	uv run pytest --tb=short -q -m "not stress and not benchmark and not fuzz"

stamp:
	uv run python scripts/check_counts.py --write

contract:
	uv run python scripts/export_contract.py --write
```

`scripts/ci-local.sh` gains two lines mirroring `typecheck` and `counts` (keep it working; it is referenced in docs).

## §6 `check_counts.py --write` mode (M0)

[DECISION] D3: Add a `--write` mode that stamps markers and visible counts; CI keeps calling read-only mode. Rationale: the audit showed the gate detects but cannot prevent drift; generation makes drift structurally impossible.

Requirements:
- `argparse` with a single flag `--write`. Default behavior byte-identical to today.
- In write mode, for each file in `_DOCS`: (1) replace any existing `<!-- codesight:counts ... -->` line with the fresh marker (insert after the H1 if absent); (2) rewrite every match of `_TEST_COUNT_PATTERNS` / `_OPS_COUNT_PATTERNS` / `_LANG_COUNT_PATTERNS` capture group with the live value, preserving comma formatting when the original had commas (badge URLs never get commas).
- New function signature: `def _stamp_text(text: str, ops: int, langs: int, tests: int) -> str:` — pure, unit-testable.
- After writing, re-run the verify pass in-process and exit 0 only if clean.
- Test file `tests/scripts/test_check_counts_write.py`, tests: `test_stamp_replaces_marker`, `test_stamp_rewrites_badge_and_prose_counts`, `test_stamp_preserves_comma_formatting`, `test_write_then_verify_is_clean`, `test_readonly_mode_unchanged_output`. Use temp copies of fixture markdown — never the live docs.

Then run `make stamp` once to fix the live drift (README.md lines 3/14/59 badge+prose, and `docs/{index,project-overview,architecture,development-guide,source-tree-analysis}.md`), commit as `M0.x: regenerate doc counts (2562 -> live)`.
